# BUG-002 — Interface consulta endpoint inexistente e exibe API indisponível

**Origem:** OBS-02 do registro do PO (01/11/2026)
**Critério afetado:** CT-M01.3c (estado de erro da interface)
**Severidade:** Média — indica indisponibilidade falsa ao usuário
**Estado:** Corrigido na branch `dev`, não integrado à `main`
**Responsável:** Frontend (#9)

## Passos para reproduzir

1. Subir a aplicação a partir da `main` e abrir a interface na porta 3000.
2. Observar a mensagem de disponibilidade da API.
3. Comparar com `GET /healthz` direto na porta 8000.

## Esperado

A interface consulta a sonda que o backend realmente expõe (`/healthz`) e mostra
disponível. `GET /healthz` na porta 8000 responde 200.

## Obtido

A interface recebe **HTTP 404** e exibe API indisponível.

## Causa raiz — confirmada no código

O proxy do Vite reescreve `/api` **removendo o prefixo**:

`frontend/vite.config.ts` → `rewrite: (pathStr) => pathStr.replace(/^\/api/, '')`

Na `main`, `frontend/src/components/ApiStatus.tsx` chama `/api/health` → o backend
recebe `/health` → 404, porque expõe `/healthz` e `/readyz`.

Na `dev`, a chamada passou a ser `${apiBaseUrl}/healthz` = `/api/healthz` → reescrito
para `/healthz` → 200.

**O defeito é o nome do endpoint, não o proxy.** Corrigir o proxy teria mascarado o
erro em vez de resolvê-lo.

## Ambiente

`main` @ `5a35330`; correção presente em `origin/dev`.

## Impacto

Usuário conclui que o backend está fora do ar com o backend saudável. Em demonstração,
isso vira pergunta do avaliador.

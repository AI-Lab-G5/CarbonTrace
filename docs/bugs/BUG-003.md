# BUG-003 — Ambiente limpo subia sem fatores e sem contas de demonstração

**Origem:** OBS-03 do registro do PO (01/11/2026)
**Critério afetado:** CA-08 (smoke em checkout limpo)
**Severidade:** Média — exigia preparação manual não documentada
**Estado:** **Fechado** — corrigido no PR #30
**Responsável:** DevOps (#13)

## Passos para reproduzir

1. Checkout limpo, `docker compose up --build`.
2. Sem rodar nenhum script manual, conferir o catálogo de fatores e as contas de Auth.

## Esperado

Ambiente pronto conforme o guia: catálogo de fatores publicado e contas de demonstração
disponíveis.

## Obtido (antes da correção)

Zero fatores e zero contas. O emulador iniciava vazio; qualquer login retornava
`EMAIL_NOT_FOUND`.

## Correção aplicada

- `backend/scripts/seed_contas.py` — cria uma conta por empresa no Auth Emulator, com
  e-mail verificado e claims `tenant_id` + `papel=funcionario`. Idempotente; recusa rodar
  sem `FIREBASE_AUTH_EMULATOR_HOST`.
- Serviço `seed` no `docker-compose.yml` roda os dois seeds (`restart: "no"`).
- Backend passa a esperar `service_completed_successfully`.
- `make seed` → `docker compose run --rm seed`.

Contas: `demo-a@carbontrace.local` / `demo-b@carbontrace.local`, senha
`carbontrace-demo`.

## Verificação

Job `deny-all` do CI (run `41654224125`) sobe os emuladores, roda o seed e executa os
9 casos de Rules com token real — verde. Ensaio de `docker compose up` confirmado pelo
@Thomas4ugust0.
